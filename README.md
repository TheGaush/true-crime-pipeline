# True-Crime Documentary Pipeline: Architecture & Engineering Blueprint (v4)

An architecture, executable SQLite v4 schema, Mermaid diagram atlas, cited research corpus, and 200-task parallel engineering blueprint for a single-host local desktop workflow designed to produce up to **10 twenty-minute (1,200-second) stylized true-crime documentaries per month**.

> **Explicit Scope Notice (`F-08`):** This repository is the **architecture specification, executable SQLite v5 DDL/test suite (`schema/pipeline.sql`, `schema/schema-test.js`), Mermaid atlas, and 200-task implementation plan (`IMPLEMENTATION_TASKS.md`)**—NOT an already-deployed application runtime. Passing `node schema/schema-test.js` (`16/16`) validates schema constraints only; application behavior and live provider contracts are validated when runtime packages are built per [IMPLEMENTATION_TASKS.md](IMPLEMENTATION_TASKS.md) using **offline zero-spend transport mocks by default** (`F-01`), followed by one bounded post-integration live connectivity check. Existing v4 databases upgrade through [schema/MIGRATION_0005.md](schema/MIGRATION_0005.md).

## Key Engineering & Safety Guarantees (v4 Audit-Hardened)

1. **Zero-Spend Offline-by-Default Testing + Deferred Live Check (`F-01`, schema v5):** Every standard unit, integration, worktree, and CI test MUST run offline behind HTTP/SDK transport mocks, socket-blocking guards, and scrubbed API credentials. `trg_offline_test_zero_spend_guard` blocks a positive estimate on insert, and `trg_budget_settlement_guard` blocks a later update that gives `OFFLINE_TEST` a positive estimate or actual. Live provider connectivity stays a single opt-in check (`Task 200`). That check is `LIVE_SANDBOX` and is capped at `$2.00` for the life of the ledger, including retries.
2. **Global Across-All-Providers Monthly Budget Ledger (`F-02`, schema v5):** Authoritative USD reservations in `pipeline.db` enforce the `$135/mo` cap, per-provider caps, and the `$10.40/ep` video cap on **insert and settlement**. A positive actual charge cannot be marked `RELEASED`. `OFFLINE_TEST` stays at `$0` after update. `LIVE_SANDBOX` has a separate lifetime cap of `$2`, including retries. Hero clip count and duration are cumulative in `flow_jobs`. See [schema/MIGRATION_0005.md](schema/MIGRATION_0005.md).
3. **Versioned `ScenePlan` Contract & "Plan First -> Creation Second -> Editing Last" (`F-05`, `F-06`):** Every scene owns a versioned `scene_plans` contract tying story purpose, intended audience effect, approved narration hash, cited `fact_ledger` IDs, visual concept, prompt, expected output, transitions, SFX, edit instructions, and acceptance checks (`DRAFT -> PLAN_APPROVED -> ASSETS_CREATED -> EDITED_APPROVED`). Upstream narration edits trigger automatic asset invalidation (`STALE_NEEDS_REAPPROVAL`). Global narrative quality comes from a structured **`craft_rubric.yaml`** (`<= 150 lines`, clarifying "interactive" strictly as visual documentary pacing/engagement)—never a brittle 4,000-line monolithic prompt.
4. **Honest ASR Architecture (`F-03`):** Local **WhisperX forced alignment** owns all millisecond word-level timestamps on `48 kHz` audio; optional cloud ASR (DeepSeek Speech-to-Text / Gemini Transcribe) is sliced cleanly to mono `16 kHz` FLAC `<= 90s / <= 4 MiB` (respecting DeepSeek's `8 MiB / 120s` limit and lack of word-level timestamps).
5. **Single Canonical v4 Contract & Wave-Ordered Worktree Merge (`F-04`, `F-07`):** Reconciles every spec, SQL schema, diagram, and task to **Schema v4**, **`gemini-omni-1.2-flash`** Interactions API (`TEXT_TO_VIDEO` / `FIRST_FRAME` / `FIRST_AND_LAST_FRAME <= 10s`), **`MAX_HERO_CLIPS = 10` / `80s`**, **`MOTIF_REGISTRY_V1`**, and a dependency-ordered **Wave Merge Runbook** (`CONTRIBUTING_AGENTS.md`).
